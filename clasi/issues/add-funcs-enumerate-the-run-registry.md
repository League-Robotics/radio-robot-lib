# Add `FUNCS` — enumerate the `RUN` registry

## Description

The v6 wire has no way to ask a robot **what is callable by name**. `RUN <function>
[arg...] #id` is fully specified (`docs/design/protocol.md` §6.3) and fully dispatched —
`decodeRun`/`execRun` in `src/protocol/protocol_handler.cpp` parse the function name and
the raw argument tokens and hand them to `Adapter::onRun()` — but nothing on the wire
enumerates the names that would resolve.

Add a new sequenced verb **`FUNCS`** that lists the adapter's registered function names,
each with an optional signature token, plus the `Adapter` seam methods that let a concrete
adapter declare that registry.

Wire shape:

```
FUNCS #7
funcs add int,int->int
funcs blink int->void
funcs ping ->int
ack 7 0 none
```

Stakeholder decisions (2026-09-07, directed out of process):

| question | decision |
|---|---|
| verb name | `FUNCS` / reply verb `funcs` |
| reply shape | one `funcs` line per registered function |
| sequenced? | **yes** — the ack is the reply's terminator, as it is for bare `GET` |
| scope | spec + handler + adapter seam + tests. No host client binding, no `rogo` surface. |

Contract details that follow from those decisions:

- `funcs <name>` when the adapter declares no signature; `funcs <name> <signature>` when
  it does.
- No `#<id>` on the `funcs` lines — matching bare `GET`'s precedent (a sequenced verb
  emitting a variable number of informational lines, terminated by its ack), not `ret`'s.
- An empty registry emits **zero** `funcs` lines — just the ack. That is the correct
  answer for an empty allowlist, not an error.
- The signature is a **single token, no spaces** (the grammar's field separator) and its
  content is unspecified — `int,int->int` is a convention, not a contract. Registered
  names must likewise be space-free, or `RUN` could never address them.

## Cause

The `RUN` design (`docs/design/protocol.md` §6.3, and `src/protocol/adapter.h`'s `onRun()`
doc block) frames a concrete adapter's registration table as "the security boundary… an
explicit allowlist" — but made that allowlist deliberately opaque. The handler holds no
function table by design, and no seam was ever added for the adapter to publish one, so a
host can only discover a callable name by guessing it and reading the `ERR_UNKNOWN`.

Compounding this: **no `Adapter` in the repo keeps a registry at all.**
`src/adapter/diffdrive_adapter.cpp`, `tests/protocol/mock_adapter.h`, and
`tests/protocol/fake_motion_adapter.h` each answer every `RUN` with `kUnknown`. The empty
allowlist is correct behavior, but there is currently no mechanism by which a non-empty
one could be declared.

## Proposed fix

### 1. Spec — `docs/design/protocol.md`

- §6 verb table: new row between `ESTOP` and `RUN` —
  `` | `FUNCS` | yes | — | one `funcs <name> [<signature>]` line per registered function | enumerates the adapter's `RUN` registry; see §6.5 ``
- `HELP`'s row: the `help` reply string is generated by walking `kCommandTable`, so it
  gains `FUNCS`. Update the literal in the table.
- §6.1 outcomes table: add `` `funcs <name> [<signature>]` `` — `FUNCS` only, emitted in
  addition to the ack, zero or more times.
- §6.3 (`RUN`): cross-reference §6.5 where it frames the registration table as the security
  boundary — discovery of the allowlist is now part of the contract.
- **New §6.5 `FUNCS` — enumerating the `RUN` registry.** State: why one line per function
  rather than a rest-of-line `help`-style reply (the 240-byte `kMaxLineBytes` cap, and
  signatures need somewhere to live); that the ack terminates the sequence; that an empty
  registry is silence plus ack, not an error; that the handler still holds no table (it
  walks the adapter's `runCount()`/`runName()`/`runSignature()`); that the signature is
  advisory with an unspecified format; and that names and signatures are adapter-supplied
  free-form text, sanitized by the handler exactly as `debug` and `ret` text is.
- §9 changelog: a dated decision entry recording the four decisions above.

### 2. Spec mirrors

- `docs/design/specification.md` §3 verb catalog (~line 72).
- `src/protocol/README.md` (~line 28) — the verbatim verb list.
- `README.md` (~line 102) and `src/adapter/README.md` — check and update if they enumerate
  the verb surface.

### 3. `src/protocol/adapter.h` — the seam

Three new pure-virtual methods next to `onRun()`, mirroring the existing
`fieldCount()`/`fieldName()` pair that bare `GET` walks:

```cpp
virtual size_t runCount() const = 0;
virtual const char* runName(size_t index) const = 0;
virtual const char* runSignature(size_t index) const = 0;  // "" == none declared
```

Pure virtual rather than defaulted, matching house style for this interface: every
implementer is forced to answer, and an adapter with no registry writes three one-liners
rather than silently inheriting a default that might be wrong. Extend `onRun()`'s doc
block — the registration table is now *discoverable*, which sharpens the allowlist
framing: registering a name publishes it to anything that can hear the channel.

### 4. `src/protocol/protocol_handler.{h,cpp}` — dispatch

- `kCommandTable[18]` → `[19]`. The array size is a hard-coded literal in **two** places:
  the declaration in `protocol_handler.h` (~line 266) and the definition in
  `protocol_handler.cpp` (~line 221).
- New row: `{"FUNCS", &ProtocolHandler::decodeNoFields, &ProtocolHandler::execFuncs}`.
  Reusing the existing `decodeNoFields` means extra fields are a decode failure
  (`nack` + `err 2`, sequence does not advance) with no new decode function needed.
- `execFuncs()` modeled on `execGet()`'s bare-`GET` loop: walk `0..runCount()-1`,
  `snprintf` into a `char buf[kMaxLineBytes + 1]` (the `+1` accounting `execRun` already
  documents — `snprintf` needs room for its own NUL), `writeLine()` each. Always sets
  `errCode = 0`.
- Run both tokens through the existing `sanitizeLineText()` before formatting.
  Adapter-supplied text must not be able to forge a second wire line — the same rule
  `execRun` applies to its `result` buffer and `sendDebug()` applies to its text.
- Declare `execFuncs` in the header alongside `execHelp`.

### 5. `Adapter` implementations — all three, since the methods are pure virtual

- `src/adapter/diffdrive_adapter.{h,cpp}` — `runCount()` returns 0, `runName`/
  `runSignature` return `""`. Extend the existing "no registration table" comment on
  `onRun()`: the empty allowlist is now *visibly* empty on the wire.
- `tests/protocol/mock_adapter.h` — a settable table beside the existing
  `fieldNames[]`/`numFields`: `runNames[]`, `runSignatures[]`, `numRuns`.
- `tests/protocol/fake_motion_adapter.h` — 0 and `""`, matching its own
  `fieldCount()`/`fieldName()`.

### 6. Tests

- `tests/protocol/protocol_shim.cpp` — new `extern "C"` setters, e.g.
  `phSetRunEntry(handle, index, name, signature)` and `phSetRunEntryCount(handle, n)`,
  following `phSetGetOverride`'s borrowed-pointer convention.
- `tests/protocol/test_protocol_harness.py` — empty registry (ack alone); N entries in
  registration order; entries with and without signatures mixed; `FUNCS x #1` extra field
  → `nack` + `err 2` with no sequence advance; `FUNCS` with no id → malformed, no reply at
  all; `FUNCS #0` stale retransmit → retransmit ack, registry never walked; an over-long
  name or signature truncates rather than overflowing; a name containing `\n` is sanitized,
  not emitted as two lines. Also update whatever asserts `HELP`'s exact output — grep for
  `help HELLO PING`.
- `tests/protocol/golden_vectors.txt` — a `FUNCS` block plus a new `runentry` SETUP key,
  wired into `_GoldenVectorRunner` in `test_protocol_harness.py`. The `HELP` vector's
  expected line changes too.

Host-side needs no change beyond one end-to-end test: `src/host/robot_v6/codec.py` holds
no verb table by design, so `funcs` lines parse under the generic reply parser, and
`test_codec.py`'s "every golden-vector reply line parses" test covers that for free.
`UNSEQUENCED_VERBS` in `reliability.py` is untouched — `FUNCS` is sequenced.

## Verification

Full suite:

```
uv run python -m pytest -q
```

Targeted while iterating:

```
uv run python -m pytest tests/protocol/ tests/adapter/ -q
```

Plus a live end-to-end case against the compiled `tools/sim` binary, which links the
**real** `ProtocolHandler` against `FakeMotionAdapter` — an empty registry, so the correct
observable outcome is an ack with no `funcs` lines before it, proving the empty-allowlist
path over actual bytes on an actual pipe. Add to
`tests/host/robot_v6/test_sim_e2e.py`, reusing its `sim_transport` fixture, `_read_until`,
and `Session`:

```python
def test_funcs_on_an_empty_registry_is_the_ack_alone(sim_transport):
    _read_until(sim_transport, lambda ls: len(ls) >= 1)  # consume the banner
    replies = []
    session = Session(sim_transport, on_reply=replies.append)
    seq_id = session.send("FUNCS")
    assert session.wait_for_ack(seq_id, timeout=3.0)
    assert not [r for r in replies if r.verb == "funcs"]
```
