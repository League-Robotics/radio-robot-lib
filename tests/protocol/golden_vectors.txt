# golden_vectors.txt -- protocol v6 cross-language conformance fixture
# (docs/protocol-v6-spec.md S11.3), for the C++ handler under
# tests/protocol/test_protocol_harness.py::test_golden_vectors.
#
# Rewritten 2026-08-20 for the space/`#id` grammar (spec commit 5a5b6da)
# -- every vector's SHAPE changed, not just its separator: the old
# `ok:0` id-less arm is now a BARE `ok` (no id token at all), and a
# supplied id is spelled `#<n>` in TRAILING position rather than a
# positional `:<id>` field.
#
# Every vector below is either a LITERAL example already written
# somewhere in the spec text (or docs/plan.md's own WHEELS acceptance
# criterion), or a mechanical instance of a format the spec states
# generically (e.g. "ok #<id>") -- written alongside the handler, per
# docs/plan.md Step 3, not authored afterward to match its output.
# Each vector cites its source in a comment.
#
# ---- format (this fixture file's own, invented for this harness --
# spec S11.3 does not prescribe one) ----
#
# Blocks are separated by one or more blank lines. Comment lines start
# with '#'. Each block is, in order:
#   zero or more SETUP lines   -- arm the mock adapter's canned answers
#   one or more ACTION lines   -- IN <wire line> or EMIT <col spec...>
#   zero or more OUT lines     -- expected reply lines, in order, OR the
#                                  single line "OUT NONE" meaning the
#                                  sink must be EMPTY after every ACTION
#                                  in the block runs
#
# The sink is cleared at the start of each block (not between actions
# within one block -- this is what lets a multi-frame TLM example
# assert thdr: appears once while t: repeats). SETUP is NOT reset
# between blocks -- each block below re-states whatever SETUP it
# needs, so blocks stay independently readable even though the driver
# does not literally recreate the adapter each time.
#
# SETUP keys:
#   identity <name> <serial> <drivetrain> <profile> <version>
#   now <uint32>
#   status <ready> <active> <connL> <connR> <otos> <wedge> <flags> <tlm>
#     (ready/active/connL/connR/otos/wedge are 0 or 1; flags is decimal,
#     formatted as hex on the wire; tlm is the literal lowercase word)
#   getoverride <name> <value>
#   setresult <ordinal>   -- Protocol::Result's declaration-order ordinal,
#                             see test_protocol_harness.py's RESULT_* map
#
# EMIT column spec: one or more "<name>:<hex0or1>:<value>" tokens (this
# is the FIXTURE FILE's own SETUP/EMIT sub-syntax, unrelated to the wire
# grammar -- it is never fed through feed(), only unpacked in Python and
# passed to phEmitTelemetry()).

# ---- 4. Session verbs ----

# HELLO's reply FORMAT is spec S4's literal
# "device NEZHA2 robot <name> <serial>" -- name/serial themselves are
# not given a concrete example in the spec text, so this harness's own
# fixed test identity fills them in.
SETUP identity testbot SN001 differential tovez 6.0.0
IN HELLO
OUT device NEZHA2 robot testbot SN001

# PING's reply value mirrors spec S10.2's own literal REPL transcript
# (">>> p(\"PING\")" -> "pong 38472"), just with the colon-era rendering
# of that same example updated to the space grammar.
SETUP now 38472
IN PING
OUT pong 38472

# ID's FORMAT is spec S4's literal "id <drivetrain> <profile> <version>";
# values are this harness's fixed test identity (same SETUP as HELLO).
SETUP identity testbot SN001 differential tovez 6.0.0
IN ID
OUT id differential tovez 6.0.0

# VER's FORMAT is spec S4's literal "ver <version>".
SETUP identity testbot SN001 differential tovez 6.0.0
IN VER
OUT ver 6.0.0

# STATUS's reply is spec S4's own literal worked example line, verbatim
# down to the field order -- "status ready=1 active=0 connL=1 connR=1
# otos=1 wedge=0 flags=<hex> tlm=pose". flags=216 is chosen deliberately
# to equal spec S6.2's own telemetry example flags value (0xd8), tying
# the two examples together instead of picking an arbitrary number.
SETUP status 1 0 1 1 1 0 216 pose
IN STATUS
OUT status ready=1 active=0 connL=1 connR=1 otos=1 wedge=0 flags=d8 tlm=pose

# HELP is "generated by walking the verb table at runtime" (spec S4);
# this is that table's exact content for this library's in-scope verb
# subset (docs/design/protocol.md S5), in spec S3.1's own table order.
IN HELP
OUT help HELLO PING ID VER STATUS HELP GET SET TLM WHEELS STOP ESTOP

# ---- 2. Grammar rules that are easy to miss ----

# "A run of spaces is ONE separator" (spec S2) -- extra spaces between
# HELLO's own zero expected fields and nothing else must not appear;
# this vector instead proves it on a verb WITH fields: multiple spaces
# between WHEELS's tokens still parse as exactly 3 fields, not 3 fields
# plus empty ones. (An "empty field between colons" was possible under
# the old grammar and explicitly is not under this one -- spec S2: "An
# empty token cannot exist between spaces.")
SETUP wheelsresult 0
IN WHEELS   100   100   1000   #5
OUT ok #5

# Leading and trailing whitespace on the line is ignored (spec S2).
SETUP now 999
IN    PING
OUT pong 999

# Blank-line and all-whitespace-line silence (spec S2: "A blank or
# all-whitespace line is ignored silently ... it does not count
# malformed") are NOT expressed as vectors in this text file -- a wire
# line consisting of ONLY trailing whitespace is exactly the kind of
# content an editor's "trim trailing whitespace on save" setting
# silently destroys, which would quietly turn "feed an all-space line"
# into "feed an empty IN action" with no visible diff. That behavior is
# tested instead in test_protocol_harness.py
# (test_blank_line_is_silently_ignored_not_malformed and
# test_all_whitespace_line_is_silently_ignored_not_malformed), as an
# explicit Python string literal where the whitespace is unambiguous.

# ---- 8.2 Ids: omitted vs #0 vs nonzero are three DIFFERENT wire
# behaviors under the new grammar (protocol_handler.h's own
# "Resolved-by-the-new-grammar" note) ----

# Omitted id: the command still executes, and its ok/err is sent once,
# BARE -- no #id token in the reply at all. Spec S7.1's own worked
# example, updated for the space grammar:
#   SET wheel_control.pid_kp 0.03   ->  ok   (no id: acked once, bare)
SETUP setresult 0
IN SET wheel_control.pid_kp 0.03
OUT ok

# Spec S7.1's own literal worked example, with an id:
#   SET wheel_control.pid_kp 0.03 #9   ->  ok #9
SETUP setresult 0
IN SET wheel_control.pid_kp 0.03 #9
OUT ok #9

# Spec S7.1's own literal parenthetical: "(or err #9 3 out of range)" --
# the same SET line, with the mock now answering kRange (ordinal 3).
SETUP setresult 3
IN SET wheel_control.pid_kp 0.03 #9
OUT err #9 3

# The id-less arm of the rejection path too -- bare `err <code>`, no
# id token, matching the bare-ok arm above.
SETUP setresult 3
IN SET wheel_control.pid_kp 0.03
OUT err 3

# Explicit `#0` -- "no ack wanted": executes silently, no reply at all,
# success or failure (spec S8.2). Legal here because SET's id is
# optional.
SETUP setresult 0
IN SET wheel_control.pid_kp 0.03 #0
OUT NONE

# Spec S8.2's own literal example: "A reused id is err #<id> 11" --
# ERR_DUPLICATE_ID (Result::kDuplicateId, ordinal 8).
SETUP setresult 8
IN SET wheel_control.pid_kp 0.03 #9
OUT err #9 11

# ---- 8.3 Error-code coverage: every code Result can produce
# (adapter.h; docs/protocol-v6-spec.md S8.3) now has at least one wire
# vector IN THIS FIXTURE -- codes 3 and 11 already had one each above
# (S7.1's and S8.2's own literal examples); this block adds the
# remaining six (1, 2, 4, 6, 8, 10) so a port author working from
# golden_vectors.txt alone, without cross-referencing the Python test
# suite, sees every code the handler can emit. SET is the vehicle for
# the adapter-Result codes since it is the one verb whose outcome is
# entirely the adapter's Result, unfiltered by any handler-level bounds
# table (S6: "the handler holds no field table, no bounds").

# ERR_UNKNOWN (Result::kUnknown, ordinal 1) -- "no such verb or field
# name". GET has no wire channel to carry this on (spec S7.1) so SET is
# the only verb that can produce it on the wire.
SETUP setresult 1
IN SET no.such.field 1.0 #4
OUT err #4 1

# ERR_BADARG (Result::kBadArg, ordinal 2) -- "malformed/non-finite
# argument, wrong arity". Two DIFFERENT sources produce this same code:
# the handler's OWN value decode failing before onSet() is ever called
# (shown here), and the adapter itself returning kBadArg for a
# well-formed value it rejects on other grounds (both wire-identical,
# by design -- S6).
SETUP setresult 0
IN SET wheel_control.pid_kp notanumber
OUT err 2

# ERR_FULL (Result::kFull, ordinal 4) -- "queue full (4 pending)".
SETUP setresult 4
IN SET wheel_control.pid_kp 0.03
OUT err 4

# ERR_UNIMPLEMENTED (Result::kUnimplemented, ordinal 5) -- "recognized,
# not wired on this build".
SETUP setresult 5
IN SET wheel_control.pid_kp 0.03 #9
OUT err #9 6

# ERR_NOT_CONFIGURED (Result::kNotReady, ordinal 6) -- "refused pre-ready".
SETUP setresult 6
IN SET wheel_control.pid_kp 0.03 #9
OUT err #9 8

# ERR_BUSY (Result::kBusy, ordinal 7) -- "subsystem in motion; retry at
# rest".
SETUP setresult 7
IN SET wheel_control.pid_kp 0.03 #9
OUT err #9 10

# ---- 5. Motion ----

# docs/plan.md Step 4's own acceptance criterion, run one step early
# because the handler alone is enough to prove it (updated for the
# space/#id grammar):
#   feed("WHEELS 100 100 1000 #5\n") -> sink contains "ok #5"
SETUP wheelsresult 0
IN WHEELS 100 100 1000 #5
OUT ok #5

# WHEELS's `id` is OPTIONAL (spec S5.2, `[#id]`) -- the 4-field vector
# above is the id-present arm; this is the id-absent arm, which now
# acks bare (no id token at all in the reply).
SETUP wheelsresult 0
IN WHEELS 100 100 1000
OUT ok

# WHEELS rejected: ERR_RANGE (Result::kRange, ordinal 3) -- e.g. the
# adapter enforcing spec S5.2's 5000 ms ceiling (protocol_handler.h
# ambiguity note #1: the handler itself does not enforce it).
SETUP wheelsresult 3
IN WHEELS 100 100 9000 #6
OUT err #6 3

# STOP's reply format is spec S5.4's literal "ok #<id> on enqueue";
# spec never states a concrete id for it, so id 7 is this fixture's own
# choice (it happens to match S10.2's unrelated "ok #7" MOVE example,
# which is a coincidence of format, not a shared source).
SETUP stopresult 0
IN STOP #7
OUT ok #7

# STOP rejected: ERR_BUSY (Result::kBusy, ordinal 7) -- STOP's id is
# REQUIRED (spec S3.1's `STOP #id`, no brackets) so unlike SET/WHEELS
# there is no id-0-suppresses-ack carve-out; it is always acked, even
# on rejection.
SETUP stopresult 7
IN STOP #11
OUT err #11 10

# STOP's id is REQUIRED, and spec S8.2 states explicitly: "#0 is legal
# only where the id is optional ... on MOVE/GOTO/STOP it is malformed."
# A literal "STOP #0" is therefore malformed, not a silent-execute --
# and since the very token that would have been the id is #0 (well
# formed but ZERO), the generic last-token recovery rule (spec S2) also
# does not fire: no reply at all, just the malformed count (not
# independently observable from this fixture format, hence OUT NONE).
IN STOP #0
OUT NONE

# ESTOP: spec S8.2, literal requirement -- "ESTOP never carries an id
# and is never acked". There is no wire text to quote because the
# whole point is that NOTHING is sent.
IN ESTOP
OUT NONE

# ---- 2. Malformed-line id recovery (spec S2): "If the line's last
# token is a well-formed nonzero #id, reply err #<id> <code> --
# including unknown verbs." ----

# A totally UNKNOWN verb whose last token is a well-formed nonzero #id
# still gets acked against that id -- ERR_UNKNOWN (code 1). This is the
# case that inverts the old (colon-era) "no id is knowable for an
# unknown verb" assumption: under the new self-marking grammar the id
# is recoverable independent of whether the verb itself is known.
IN FROB 1 2 3 #42
OUT err #42 1

# The same recovery rule on a KNOWN verb with wrong arity -- PING takes
# zero fields, so a trailing #id-shaped token is itself the "extra"
# field that makes the line malformed, and it is also recoverable.
IN PING #5
OUT err #5 2

# A malformed line whose last token is #0 (well-formed, but NOT
# nonzero) gets NO reply -- spec S2's rule is "well-formed NONZERO
# #id", and S8.2 confirms id 0 never triggers an err reply either.
IN FROB #0
OUT NONE

# A malformed line whose last token does not even look like an id at
# all (no leading '#') gets no reply, same as before this grammar
# switch -- there is nothing self-marking to recover.
IN FROB 1 2 3
OUT NONE

# ---- 6. Telemetry ----

# Spec S6.2's own literal worked example, verbatim in content, updated
# for the space grammar:
#   thdr seq now flags x y h ox oy oh
#   t 412 38472 d8 -1234 892 1571 -1240 889 1573
#   t 413 38504 d8 -1198 901 1571 -1205 898 1572
# Two EMITs in one block: thdr is due once (column set has never been
# seen), then t on every call thereafter.
EMIT seq:0:412 now:0:38472 flags:1:216 x:0:-1234 y:0:892 h:0:1571 ox:0:-1240 oy:0:889 oh:0:1573
EMIT seq:0:413 now:0:38504 flags:1:216 x:0:-1198 y:0:901 h:0:1571 ox:0:-1205 oy:0:898 oh:0:1572
OUT thdr seq now flags x y h ox oy oh
OUT t 412 38472 d8 -1234 892 1571 -1240 889 1573
OUT t 413 38504 d8 -1198 901 1571 -1205 898 1572
