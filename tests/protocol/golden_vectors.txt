# golden_vectors.txt -- cross-language conformance fixture (see
# docs/design/protocol.md's "archetype" framing), for the C++ handler
# under tests/protocol/test_protocol_harness.py::test_golden_vectors.
#
# Rewritten 2026-08-22 for the six stakeholder-directed changes
# (docs/design/protocol.md §8.9): a decode failure (unknown verb, wrong
# arity, unparseable field) now NACKs and does NOT advance the sequence
# -- only a merits rejection (a well-formed line the ADAPTER refuses)
# still acks-then-errs; `ERR_DUPLICATE_ID` is gone; `PING` joins
# `HELLO`/`ESTOP` as unsequenced (no id, always answers); every
# `ack`/`nack` now carries a THIRD token, the completion reason
# (`none`/`stop`/`timeout`/`estop`/`aborted`) alongside the id and
# `lastDone`; and `WHEELS` is renamed `WHEELS_V`, joined by five new
# motion verbs (`WHEELS_X`/`MOVE_X`/`MOVE_V`/`GO_TO_R`/`GO_TO_W`) from
# docs/design/motion-api.md §9.1.
#
# Every vector below is either a literal example written alongside the
# handler as it was built, or a mechanical instance of a format the
# design states generically -- not authored afterward to match the
# implementation's output. Each vector cites its source in a comment.
#
# ---- format (this fixture file's own, invented for this harness) ----
#
# Blocks are separated by one or more blank lines. Comment lines start
# with '#'. Each block is, in order:
#   zero or more SETUP lines   -- arm the mock adapter's canned answers
#   one or more ACTION lines   -- IN <wire line> or EMIT <col spec...>
#   zero or more OUT lines     -- expected reply lines, in order, OR the
#                                  single line "OUT NONE" meaning the
#                                  sink must be EMPTY after every ACTION
#                                  in the block runs
#
# The sink is cleared at the start of each block. SETUP is NOT reset
# between blocks -- each block re-states whatever SETUP it needs.
#
# SETUP keys:
#   identity <name> <serial> <drivetrain> <profile> <version>
#   now <uint32>
#   status <ready> <active> <connL> <connR> <otos> <wedge> <flags> <tlm>
#   getoverride <name> <value>
#   setresult <ordinal>       -- Protocol::Result's declaration-order
#                                 ordinal, see test_protocol_harness.py's
#                                 RESULT_* map
#   wheelsresult <ordinal>    -- WHEELS_V's own Result
#   stopresult <ordinal>
#   runresult / runhasresult / runresulttext
#   lastdone <uint32>         -- Adapter::lastDone() (2026-08-22)
#   lastdonereason <ordinal>  -- Adapter::lastDoneReason()'s
#                                 declaration-order ordinal, see
#                                 test_protocol_harness.py's DONE_* map
#
# EMIT column spec: one or more "<name>:<hex0or1>:<value>" tokens.
#
# ---- sequencing note ----
#
# Every block below runs against a HANDLE THAT HAS JUST BEEN RESET
# (test_golden_vectors sends a fresh "HELLO\n" at the top of every
# block, resetting expectedNext_ to 1). `lastdone`/`lastdonereason` are
# SETUP on the mock adapter directly (not reset by HELLO -- HELLO no
# longer touches the Adapter's own completion state at all, docs/design/
# protocol.md §8.9), so a block that wants a non-default reason states
# it explicitly every time, same as `wheelsresult` etc.

# ---- Session verbs ----

# HELLO's reply FORMAT is spec's literal
# "device NEZHA2 robot <name> <serial>". HELLO is unsequenced and
# carries no id (docs/design/protocol.md §8.3).
SETUP identity testbot SN001 differential tovez 6.0.0
IN HELLO
OUT device NEZHA2 robot testbot SN001

# PING (2026-08-22): unsequenced, no id, no ack -- just the bare `pong`
# reply. This is the change from before: PING used to require a
# mandatory id and get an `ack` line of its own; now it answers
# immediately regardless of sequence state, exactly like ESTOP.
SETUP now 38472
IN PING
OUT pong 38472

# PING tolerates (and ignores) trailing content, including something
# that LOOKS like an old-style id -- maximally forgiving, matching
# ESTOP's own posture (this file's own resolved ambiguity, protocol_
# handler.h's ambiguity note #4).
SETUP now 111
IN PING #7
OUT pong 111

# ID's FORMAT is "id <drivetrain> <profile> <version>"; ack now carries
# lastDone/reason too.
SETUP identity testbot SN001 differential tovez 6.0.0
IN ID #1
OUT ack 1 0 none
OUT id differential tovez 6.0.0

SETUP identity testbot SN001 differential tovez 6.0.0
IN VER #1
OUT ack 1 0 none
OUT ver 6.0.0

# STATUS's reply is spec's own literal worked example line, verbatim
# down to the field order.
SETUP status 1 0 1 1 1 0 216 pose
IN STATUS #1
OUT ack 1 0 none
OUT status ready=1 active=0 connL=1 connR=1 otos=1 wedge=0 flags=d8 tlm=pose next=2

# HELP lists every verb, generated by walking the same table dispatch()
# uses -- includes the six-verb motion set, WHEELS_V (not WHEELS), and
# both PING and ESTOP even though neither is looked up through this
# table for real dispatch.
IN HELP #1
OUT ack 1 0 none
OUT help HELLO PING ID VER STATUS HELP GET SET TLM WHEELS_X WHEELS_V MOVE_X MOVE_V GO_TO_R GO_TO_W STOP ESTOP RUN

# ---- Grammar rules that are easy to miss ----

# "A run of spaces is ONE separator" -- extra spaces between WHEELS_V's
# tokens still parse as exactly 3 data fields plus the mandatory id.
SETUP wheelsresult 0
IN WHEELS_V   100   100   1000   #1
OUT ack 1 0 none

# Leading and trailing whitespace on the line is ignored.
SETUP now 999
IN    PING
OUT pong 999

# ---- The reliability layer: mandatory ids, ack/nack, ack/nack's
# reason token, `#0` no longer suppressing anything ----

# SET's own worked example: the ack alone is the acceptance signal.
SETUP setresult 0
IN SET wheel_control.pid_kp 0.03 #1
OUT ack 1 0 none

# The same SET, now rejected on MERITS (kRange, ordinal 3): a merits
# rejection still ACKS (it arrived, in order, decoded fine) -- the err
# follows, code first, id last.
SETUP setresult 3
IN SET wheel_control.pid_kp 0.03 #1
OUT ack 1 0 none
OUT err 3 #1

# `#0` is unconditionally a stale retransmit on a freshly-reset handle
# (expectedNext_ starts at 1) -- acked against 0, nothing accepted yet.
SETUP setresult 0
IN SET wheel_control.pid_kp 0.03 #0
OUT ack 0 0 none

# A sequenced verb with NO id at all is malformed -- no reply of any
# kind (the id itself could not be resolved, so there is nothing to
# nack against either).
IN PING_TYPO
OUT NONE

# The ack/nack reason token reflects whatever the Adapter currently
# reports -- exercised directly here (2026-08-22, docs/design/
# protocol.md §8.8: "the ack/nack piggyback rides along"). ID is the
# vehicle (rather than STATUS, whose own reply line would otherwise need
# repeating in full here) since its own reply never varies with
# lastDone/lastDoneReason.
SETUP identity testbot SN001 differential tovez 6.0.0
SETUP lastdone 7
SETUP lastdonereason 1
IN ID #1
OUT ack 1 7 stop
OUT id differential tovez 6.0.0

SETUP identity testbot SN001 differential tovez 6.0.0
SETUP lastdone 12
SETUP lastdonereason 3
IN ID #1
OUT ack 1 12 estop
OUT id differential tovez 6.0.0

# Reset back to the default for every block below -- SETUP is NOT
# reset between blocks (this file's own header note), so the two
# demonstration vectors above would otherwise "poison" every later
# block's own expected ack/nack reason token.
SETUP lastdone 0
SETUP lastdonereason 0
IN HELP #1
OUT ack 1 0 none
OUT help HELLO PING ID VER STATUS HELP GET SET TLM WHEELS_X WHEELS_V MOVE_X MOVE_V GO_TO_R GO_TO_W STOP ESTOP RUN

# ---- Error-code coverage: every REACHABLE code Result can produce has
# at least one wire vector. Code 11 (ERR_DUPLICATE_ID) no longer exists
# on Protocol::Result at all (2026-08-22) -- there is nothing left to
# demonstrate. SET is the vehicle for the adapter-Result codes since its
# outcome is entirely the adapter's Result. Every vector below is its
# own block, so every id is #1.

SETUP setresult 1
IN SET no.such.field 1.0 #1
OUT ack 1 0 none
OUT err 1 #1

# ERR_BADARG via a HANDLER-level decode failure -- this is now a NACK,
# not an ack+err (2026-08-22's central behavior change): the value
# field never parses, so the line never "arrived intact", and the
# sequence does NOT advance.
SETUP setresult 0
IN SET wheel_control.pid_kp notanumber #1
OUT nack 1 0 none
OUT err 2 #1

SETUP setresult 4
IN SET wheel_control.pid_kp 0.03 #1
OUT ack 1 0 none
OUT err 4 #1

SETUP setresult 5
IN SET wheel_control.pid_kp 0.03 #1
OUT ack 1 0 none
OUT err 6 #1

SETUP setresult 6
IN SET wheel_control.pid_kp 0.03 #1
OUT ack 1 0 none
OUT err 8 #1

SETUP setresult 7
IN SET wheel_control.pid_kp 0.03 #1
OUT ack 1 0 none
OUT err 10 #1

# ---- Motion: the six verbs (docs/design/motion-api.md §9.1) ----

# WHEELS_V (renamed from WHEELS, 2026-08-22 -- docs/design/motion-api.md
# §9.2 confirms WHEELS *is* wheels_v; same fields, same meaning).
SETUP wheelsresult 0
IN WHEELS_V 100 100 1000 #1
OUT ack 1 0 none

SETUP wheelsresult 3
IN WHEELS_V 100 100 9000 #1
OUT ack 1 0 none
OUT err 3 #1

# WHEELS_X: per-wheel commanded DISTANCE, not velocity -- has no prior
# wire form at all before this change.
SETUP wheelsxresult 0
IN WHEELS_X -100 100 200 5000 #1
OUT ack 1 0 none

SETUP wheelsxresult 3
IN WHEELS_X 100 100 200 5000 #1
OUT ack 1 0 none
OUT err 3 #1

# MOVE_X: body displacement + heading change. rotation is a milliradian
# INTEGER on the wire (docs/design/motion-api.md §9.1) -- 1571 mrad is
# approximately pi/2 (a 90-degree turn), decoded as an ordinary signed
# field, no different from any other integer.
SETUP movexresult 0
IN MOVE_X 400 1571 200 5000 #1
OUT ack 1 0 none

SETUP movexresult 1
IN MOVE_X 400 -1571 200 5000 #1
OUT ack 1 0 none
OUT err 1 #1

# MOVE_V: body twist, held for `duration`.
SETUP movevresult 0
IN MOVE_V 150 0 1000 #1
OUT ack 1 0 none

SETUP movevresult 2
IN MOVE_V 150 500 1000 #1
OUT ack 1 0 none
OUT err 2 #1

# GO_TO_R / GO_TO_W: identical wire shape, different frame -- the
# handler does not distinguish them beyond the verb name itself.
SETUP gotorresult 0
IN GO_TO_R 300 -150 150 10 5000 #1
OUT ack 1 0 none

SETUP gotowresult 0
IN GO_TO_W 300 -150 150 10 5000 #1
OUT ack 1 0 none

# ---- STOP: the ack alone on success; the optional `now` token
# (docs/design/motion-api.md §3.7/§9.1) sits safely before the id since
# the id is self-marking ----

SETUP stopresult 0
IN STOP #1
OUT ack 1 0 none

SETUP stopresult 0
IN STOP now #1
OUT ack 1 0 none

SETUP stopresult 7
IN STOP #1
OUT ack 1 0 none
OUT err 10 #1

# A token that ISN'T the literal "now" is wrong arity -- a HANDLER-level
# decode failure, so this NACKS (2026-08-22), not acks-then-errs.
IN STOP later #1
OUT nack 1 0 none
OUT err 2 #1

# ESTOP: unsequenced, maximally forgiving, replies `estop`. Executed
# before the reply is written.
IN ESTOP
OUT estop

IN ESTOP #5
OUT estop

# ---- Decode failure is a NAK (2026-08-22, docs/design/protocol.md
# §8.9) -- the central behavior change this fixture exists to pin. Two
# distinct cases, kept distinct: a decode failure (the line did not
# arrive intact) NACKS and does NOT advance the sequence; a merits
# rejection (SET's own unknown-field-name vector above) ACKS and
# advances. ----

# A totally UNKNOWN verb, in order: a decode failure -- NACK (naming
# THIS SAME id, since it was never accepted) plus err. Compare against
# the pre-2026-08-22 behavior this fixture used to show here: "ack 1 0"
# followed by "err 1 #1" -- that shape is GONE.
IN FROB 1 2 3 #1
OUT nack 1 0 none
OUT err 1 #1

# The same recovery on a KNOWN verb with wrong arity -- ID takes zero
# data fields, so one extra field is a decode failure too. Resending
# the SAME id, now well-formed (still in the SAME block, so the
# sequence state carries over), is what actually advances the sequence
# -- proving the NACK really did hold #1 in place rather than silently
# consuming it.
IN ID extra #1
IN ID #1
OUT nack 1 0 none
OUT err 2 #1
OUT ack 1 0 none
OUT id differential tovez 6.0.0

# A sequenced verb whose only field is a MALFORMED id (no leading '#',
# or non-digit content after one) cannot be sequence-classified at
# all -- no reply of any kind, unaffected by this change (there is no
# id to nack against).
IN FROB notanid
OUT NONE

# ---- Telemetry ----

# Two EMITs in one block: thdr is due once, then t on every call
# thereafter -- PLUS the reliability layer's own periodic line, now
# carrying the reason token too. This handle has just been HELLO-reset
# and never accepted any sequenced command, so "ack 0 0 none" both
# times.
EMIT seq:0:412 now:0:38472 flags:1:216 x:0:-1234 y:0:892 h:0:1571 ox:0:-1240 oy:0:889 oh:0:1573
EMIT seq:0:413 now:0:38504 flags:1:216 x:0:-1198 y:0:901 h:0:1571 ox:0:-1205 oy:0:898 oh:0:1572
OUT thdr seq now flags x y h ox oy oh
OUT t 412 38472 d8 -1234 892 1571 -1240 889 1573
OUT ack 0 0 none
OUT t 413 38504 d8 -1198 901 1571 -1205 898 1572
OUT ack 0 0 none

# The same piggyback, but after a real command has been accepted first.
SETUP wheelsresult 0
IN WHEELS_V 100 100 1000 #1
EMIT seq:0:1 now:0:2 x:0:3
OUT ack 1 0 none
OUT thdr seq now x
OUT t 1 2 3
OUT ack 1 0 none

# The nack arm: a gap left outstanding keeps producing nack at the
# telemetry rate until the gap is filled.
IN WHEELS_V 100 100 1000 #5
EMIT seq:0:1 now:0:2 x:0:3
OUT nack 1 0 none
OUT t 1 2 3
OUT nack 1 0 none

# ---- debug: robot-to-host only, unaffected by any of these changes ----

DEBUG something happened
OUT debug something happened

DEBUG
OUT debug

IN debug something happened
OUT NONE

# ---- RUN: invocation by name -- unaffected in its OWN merits-rejection
# codes (unknown function / bad arg are still the adapter's own call,
# same as SET's unknown-field-name case), but its structural decode
# failures (no function name at all; too many raw tokens) NOW NACK
# rather than ack-then-err ----

SETUP runresult 0
SETUP runhasresult 0
IN RUN blink #1
OUT ack 1 0 none

SETUP runresult 0
SETUP runhasresult 1
SETUP runresulttext 42
IN RUN add 19 23 #1
OUT ack 1 0 none
OUT ret 42 #1

SETUP runresult 0
SETUP runhasresult 1
SETUP runresulttext 42
IN RUN add 19 23 #0
OUT ack 0 0 none

# Unknown function name -- a MERITS rejection (the adapter's own call,
# RUN's grammar was satisfied), so this still acks then errs.
SETUP runresult 1
IN RUN no_such_function #1
OUT ack 1 0 none
OUT err 1 #1

SETUP runresult 2
IN RUN add one two #1
OUT ack 1 0 none
OUT err 2 #1

# RUN with NO function name at all, but a well-formed id that consumes
# the line's only field -- a STRUCTURAL decode failure now (2026-08-22):
# there is no function name left once the id is accounted for, so this
# NACKS, it does not ack-then-err.
IN RUN #1
OUT nack 1 0 none
OUT err 2 #1

# The bare-verb arm of the same rule: nothing at all after RUN, so
# there is no id to sequence-check against either -- no reply of any
# kind, unaffected by this change.
IN RUN
OUT NONE

# ---- TLM HDR: header recovery request (docs/design/protocol.md §10.5,
# sprint 003 ticket 003) ----

# Continues directly from the telemetry blocks above: headerNames_ is
# still ["seq","now","x"], everEmittedHeader_ still true -- the
# "WHEELS_V ... #5 / EMIT seq:0:1 now:0:2 x:0:3" block just above
# already proved that SAME column set does NOT re-emit thdr on its own.
# TLM HDR #1 is accepted and acked like any other sequenced TLM form --
# no err line, and no telemetry output of its own -- but it clears the
# remembered header, so the very next EMIT with the IDENTICAL column set
# re-emits thdr anyway: proof the re-emit came from TLM HDR, not from
# any column-set change.
IN TLM HDR #1
EMIT seq:0:9 now:0:99 x:0:1
OUT ack 1 0 none
OUT thdr seq now x
OUT t 9 99 1
OUT ack 1 0 none
